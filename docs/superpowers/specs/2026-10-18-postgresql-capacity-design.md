# V2 PostgreSQL 迁移与同负载复测

用户目标：把当前混合压测的数据库从 MySQL 改为 PostgreSQL 再测一次。应用继续 8 核、4 GiB；3 个逻辑池各 64，200 用户，7 查询/1 查单/1 兑换/1 抽奖，5/100/300/600 VU 各 45 秒，无固定 RPS。沿用认证、事务、幂等、截止时间和后台交付语义。

范围为当前 V2 业务链路，不移植未参与本轮测试的旧 V1 MyBatis 业务。保留 MySQL 运行方式和原始证据；PostgreSQL 使用新容器、卷和三库。不能通过关闭 durable commit 获得虚假收益。

适配：集中、可测试的 PostgreSQL SQL 兼容层处理已知 V2 SQL；在路由连接边界按 JDBC URL 选择，MySQL不经过转换，底层 Hikari保持原始预算/监控可见性。PostgreSQL独立DDL明确主键/唯一约束、JSON、时间与二进制类型；避免冲突异常导致整事务失效，验证幂等冲突返回与原有一致。未知语法必须失败，不能静默吞错。

验证：真实PostgreSQL建表、事务和并发幂等、HTTP预置交付、混合请求、停写对账；保存错误、SQL/锁/I/O等待、CPU/RAM、成功QPS、成功及全部请求P99、最终交付与积压。上一轮MySQL直连为参考，数据库版本/缓存/持久性/资源差异明确，不能当多轮严格数据库性能排名。实现后独立审查。
