# 本地 V2 关闭业务限流压测：2 核 4 GiB

## 范围与生效证据

按照“把所有限制关闭”的压测指令，使用测试启动器 `--probe.unlimited=true`：入口用户/活动/查询/取消 RPS、入口交易/查询/取消并发检查全部跳过，不再调用 Redis 限流 Lua 或本地降级限流。数据库 TRADE/QUERY/WORKER/CALLBACK/RELAY/RECOVERY 信号量分别配置为 Integer.MAX_VALUE，在本轮规模下不会形成许可瓶颈；沿用在途计数、指标和有序关闭。

**这不等于无限物理资源**：仍保留单实例 2 CPU / 4 GiB、Xmx2g，每逻辑库 Hikari 8 个连接、后台执行器调度容量、请求/SQL 超时、认证和业务不变量。未关闭数据库行锁、资金条件更新、幂等、Outbox 原子事务或库存约束。

启用代码仅在 `src/test/java`，默认关闭；校验 v2-it 与同一运行命名空间的三库环境变量。固定压测脚本额外预检真实本地依赖端点和容器身份。此 helper 的 schema 校验自身不替代真实端点预检。

现场证据 `effective-limits.json` 校验实际 RequestAdmission 类型、六类可用许可；外部 Docker/cgroup 记录验证 2 CPU 和 4294967296 字节。指标观测到三个 Hikari pool max 均为 8。生产 **576 个 class SHA 未变**，生产 JAR 不包含无业务限流 helper 或故障启动器。
