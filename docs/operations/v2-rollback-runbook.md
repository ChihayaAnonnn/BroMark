# 停止与恢复

触发：任何未解释账实差异、旧写混入、已受理订单无终态且无持久核查单、持续积压增长、预算超限、延迟持续超门限。

1. 先停止所有实例新交易准入，保留查单、回调、Worker、Relay和恢复预算。记录停止点、镜像/配置、订单水位和队列状态。
2. 禁止认领新运维任务；已有已受理交易继续由理解V2协议的Worker排空。关闭进程时按受理→认领→在途事务/确认→线程池→连接顺序，超时依靠租约接管。
3. 核对source订单、Outbox/Inbox/Retry、库存HELD/CONFIRMED/取消墓碑、支付事实与原回执。积压0不能替代六域对账；每个已受理订单必须终态或有持久核查单。
4. 差异进入REVIEW/WAITING_FIX；留业务状态、原bizId、内容摘要、操作人和原因。按v2-recovery-runbook审计恢复，禁止直接改余额、删除任务或批量释放预留。
5. 恢复同一V2兼容版本的Worker，先验证原回执重放，再小量恢复新增。DDL中断核对information_schema与cutover_audit，使用原checksum输入重入；不DROP、不逆向改旧状态。
6. 不能将新协议中间状态交给旧实现；恢复旧活动之前必须再次排空/审计。共享账户始终使用统一资产内核，旧通用无流水写入永不重开。

成功证据：停止后新增0；在途排空或租约可接管；六域已检查且差异0；核查单有责任人与处理记录；恢复后重复消息无新资产效果。未满足则保持停止新增，不能宣称回滚完成。
